# BE10000 SSH 开关

控制台的“资源监控”页内提供紧凑的 SSH 状态卡片，不增加侧边栏栏目。接口为已登录且受 CSRF 保护的 `GET /api/ssh` 与 `POST /api/ssh/action`，操作只接受 `enable` 或 `disable`，不接受任意命令或路径。

该功能只在 RC01 上启用，并要求已有的 `/data/etc/be10000-ssh-persist.sh` 是可执行的、已审计的持久化脚本。为让用户主动关闭后不被每分钟的 cron 重新开启，脚本开头、锁创建之前必须有这一行：

```sh
[ -e /data/etc/be10000-ssh-disabled ] && exit 0
```

部署时先备份原脚本，再插入该行并运行 `sh -n`；控制台不会自动改写 SSH 守护脚本。缺少该行、固件型号不符或 Dropbear init 不可用时，页面只显示“不支持”且禁用开关。

关闭操作先创建 root-only 标记，等待当前守护结束，然后提交 `ssh_en=0` 并停止 Dropbear。开启操作删除标记并运行已有持久化脚本；只有实际监听与控制台 LAN IPv4 地址一致、且没有其它 IPv4/IPv6 的 22 端口监听时才报告成功。开启失败会尝试重新标记关闭并停止服务。状态每五秒读取一次内核监听表与固件开关，区分“已关闭”“运行中”和“监听异常”。

关闭 SSH 会断开现有 SSH 管理连接。回滚控制台或旧守护脚本之前，先通过当前控制台重新开启 SSH；旧脚本不认识关闭标记，直接恢复会使 cron 再次开启 SSH。
